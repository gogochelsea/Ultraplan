# 01. 글자 렌더링 ★

가장 흔하고 가장 골치 아픈 함정. **잘못 만들면 텍스트가 통째로 빈 페이지로 출력**된다. 컴파일·실행 에러는 없고 .hwp 파일은 정상 크기로 저장되는데 열어보면 글자만 안 보임 → 디버깅 난이도 ★★★.

---

## 증상

| 증상 | 보이는 결과 |
|---|---|
| **A. 글자가 통째로 안 보임** | .hwp 열면 페이지는 있는데 텍스트가 빈칸 |
| **B. 글자 크기/서체가 단락마다 들쭉날쭉** | 본문 12pt 의도였는데 어떤 단락은 10pt, 어떤 건 14pt가 섞여 나옴 |
| **C. 한글은 보이는데 영문/숫자/한자가 안 보임 (또는 그 반대)** | 특정 언어 서브셋만 누락 |

---

## 원인

HWP의 `CharShape` 파라미터셋은 **언어 서브셋 7개**(`Hangul`, `Latin`, `Hanja`, `Japanese`, `Other`, `Symbol`, `User`)에 대해 각각 다음 6개 속성을 분리해서 가진다:

- `FaceName{lang}` — 폰트 이름
- `FontType{lang}` — 폰트 종류 (1=TTF, 2=HFT 등). **0이면 렌더링 실패**
- `Ratio{lang}` — 가로 배율 (100=원본)
- `Spacing{lang}` — 자간
- `Offset{lang}` — 기준선 오프셋
- `Size{lang}` — 글자 크기 비율 (100=`Height`에 명시한 값 그대로)

**`Height`(전체 높이) 만 세팅하고 위 7×6 매트릭스를 비워두면 한글 외 다른 언어가 빈 글자로 나오거나 전체가 안 보인다.**

추가로, **HWP COM은 마지막 액션의 CharShape 속성을 다음 단락에 잔류 적용**한다. 즉, 한 번 32pt 표지 글자를 쓰고 다음에 본문을 쓰면 본문도 32pt가 됨. 매 write마다 `set_char_shape`을 다시 부르지 않으면 사이즈가 섞인다.

---

## 정답 — `set_char_shape` 정형 패턴

```python
def set_char_shape(size_pt=12, bold=False, italic=False, color=0, face="함초롬바탕"):
    """매 write 직전에 호출. 7개 언어 서브셋 모두에 동일 폰트·비율 강제."""
    hwp.HAction.GetDefault("CharShape", hwp.HParameterSet.HCharShape.HSet)
    cs = hwp.HParameterSet.HCharShape
    cs.Height = int(size_pt * 100)  # HWP는 Height 단위가 0.01pt — 12pt → 1200
    cs.Bold = 1 if bold else 0
    cs.Italic = 1 if italic else 0
    cs.TextColor = color
    for ln in ["Hangul", "Latin", "Hanja", "Japanese", "Other", "Symbol", "User"]:
        setattr(cs, f"FaceName{ln}", face)
        setattr(cs, f"FontType{ln}", 1)  # ★ 1 = TTF — 0이면 렌더링 실패
        setattr(cs, f"Offset{ln}",  0)
        setattr(cs, f"Ratio{ln}",   100)
        setattr(cs, f"Spacing{ln}", 0)
        setattr(cs, f"Size{ln}",    100)
    hwp.HAction.Execute("CharShape", cs.HSet)
```

---

## 절대 빠뜨리면 안 되는 항목 체크리스트

매 `set_char_shape` 호출 시 다음을 모두 세팅했는지 확인:

- [ ] `Height = size_pt × 100` — 단위는 0.01pt
- [ ] **7개 언어 서브셋 전부**: Hangul, Latin, Hanja, Japanese, Other, Symbol, User
- [ ] 각 서브셋에 `FaceName{ln}` (폰트명)
- [ ] 각 서브셋에 `FontType{ln} = 1` ★ — TTF
- [ ] 각 서브셋에 `Ratio{ln} = 100`, `Size{ln} = 100`
- [ ] `Spacing{ln} = 0`, `Offset{ln} = 0`

하나라도 빠지면 해당 언어가 안 보이거나 비율이 깨짐.

---

## "왜 매번 호출해야 하나"

HWP COM 액션은 stateful이다. 한 번 `CharShape`을 적용하면 그 속성이 전역 상태로 유지되어 다음 단락에 그대로 적용된다. 표지 32pt 굵게로 한 번 쓰면, `set_char_shape` 재호출 없이 본문을 쓸 경우 본문도 32pt 굵게가 된다.

→ **그래서 모든 write 헬퍼(`write_line`, `write_para`)는 내부에서 매번 `set_char_shape`을 다시 부른다.** 직접 `insert_text`만 호출하면 안 됨.

이걸 안 지켜서 만들어진 .hwp의 글자 크기를 사후 보정하는 패턴은 [04-페이지와-검증.md](./04-페이지와-검증.md) 끝부분 참고. 사후 보정은 비싸고 부정확하니 처음부터 매번 호출하는 게 정답.

## 본문 표준값 (학교 사업계획서 기준)

| 용도 | size_pt | bold | align | line_space |
|---|---|---|---|---|
| 본문 일반 | 12 | False | justify | 160 |
| 소제목 (`-XX 전략`) | 12 | True | left | 160 |
| 장 제목 (`1. XX`) | 12 | True | left | 160 |
| 표지 메인 | 32 | True | center | 160 |
| 표지 부제 | 20 | True | center | 160 |
| 표 셀 본문 | 10 | False | center/left | 150 |
| 표 헤더 | 10 | True | center | 150 |
| 그림 캡션 | 11 | False | center | 160 |

폰트는 전부 **함초롬바탕** 통일.

---

## 자주 막히는 지점

- **`Height` 단위가 헷갈림**: pt가 아니고 0.01pt. 12pt → 1200. 14pt → 1400.
- **`color`는 0이 검정**: `0xRRGGBB` 형식. 빨강 = `0xFF0000`.
- **`FaceName`에 한글 폰트명 OK**: `"함초롬바탕"`, `"맑은 고딕"` 모두 동작.
- **`FontType=0`이면 system default fallback이 일어나기도 함**: 환경따라 됐다 안 됐다. 무조건 `1`로 박을 것.
